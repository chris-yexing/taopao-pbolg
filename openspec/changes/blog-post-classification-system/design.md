## Context

目前博客使用 Hugo + PaperMod 主题部署在 GitHub Pages。现有文章约 8 篇，分布在不同主题（投资、工具、认知等），但缺乏统一的分类编码体系。读者无法从 URL 或标题快速判断文章所属分类。顶栏的「首页、文章、标签」分类不清晰，读者难以找到感兴趣的内容。

## Goals / Non-Goals

**Goals:**
- 建立一套简洁、可扩展的文章分类体系（5 个分类）
- 为每篇文章分配唯一的双段式编号（分类前缀 + 序号）
- 重新设计顶栏导航，直接用分类做入口
- 重新定义首页与分类页的职责边界，避免重复

**Non-Goals:**
- 不修改 Hugo 默认 tags taxonomy 的行为
- 不引入后端或外部 API
- 不设计复杂的自动序号重编号逻辑（初期以手动指定为主）
- 不做完整的「关于」页面，下一迭代再填充

## Decisions

### 1. 分类方案

| 分类键（key） | 中文标签 | 编号前缀 | 说明 |
|---|---|---|---|
| `investment` | 投资理财 | `inv` | 股票、ETF、资产配置相关文章 |
| `growth` | 成长生活 | `growth` | 育儿、备孕、健康——具体的人生阶段和身心状态 |
| `tool` | 效率工具 | `tool` | AI 工具、PC/NAS/网络折腾等数字系统 |
| `insight` | 认知碎片 | `insight` | 心理探索、人生感悟——内省和认知层面的散点思考 |
| `misc` | 其他 | `misc` | 不属于以上分类的文章 |

> `growth` = 具体的、有阶段性的内容
> `insight` = 认知内省的、没有时间戳属性但有观点的内容
> 边界：写备孕经历 → `growth`；写从中悟出什么道理 → `insight`

**备选方案 A（层级分类）：** 使用两级分类如 `investment/etf`。**→ 暂不引入，保持简单。**

**备选方案 B（动态分类）：** 从文章的 `categories` frontmatter 字段自动推导分类前缀。**→ 排除，分组名可能变化、前缀不可控。**

### 2. 顶栏导航

**决策：用分类做导航，去掉模糊的「文章」「标签」入口。**

```
顶栏： 首页 | 投资理财 | 成长生活 | 效率工具 | 认知碎片 | 其他 | 关于
```

- `关于`：单页面 `/about/`，暂时留白，下一迭代完善
- 各分类入口对应 Hugo taxonomy 页面 `/categories/investment/` 等

### 3. 页面职责划分

**首页 = 吸引人留下来。分类页 = 帮人找到他想要的。**

| 页面 | 职责 | 形态 | 排列 | 文章数 |
|---|---|---|---|---|
| **首页** | 发现新内容、了解博客调性 | 3列缩略图网格 + Hero简介 | 日期倒序，最新在前 | 最新 6-8 篇 |
| **分类页** `/categories/investment/` | 定向阅读，找到想要的内容 | 纯列表（无缩略图） | 日期倒序 | 每页 15 篇，含翻页 |
| **标签页** `/tags/` | 按话题聚合（已有行为） | 不变 | 不变 | 不变 |
| **文章详情页** | 单篇阅读 | 不变 | — | — |

### 4. 首页方案（详细）

**Hero 区域（页面顶部）：**
- 博客名称（大字）
- 一句话简介（如「记录投资、成长、效率的个人思考」）

**文章网格：**
- 3 列网格（PC），单列堆叠（Mobile < 768px）
- 每格：16:9 缩略图（`cover` 字段；未设置则显示分类对应的纯色块）+ 标题 + 分类编号（右下角小字）
- 最新 6-8 篇（够一个首屏，不做翻页）
- 文章总数超过 8 篇时，底部加一行「浏览更多 →」链接到各分类页

**缩略图方案：**
- 有 `cover` 字段：直接使用
- 无 `cover` 字段：显示纯色块，颜色按分类固定（`inv` 深蓝 / `growth` 绿 / `tool` 橙 / `insight` 紫 / `misc` 灰）

### 5. 分类页方案（详细）

- 纯列表，无缩略图，干净高效
- 每条目：标题 + 日期 + 分类编号
- 日期倒序（最新在前）—— 定向读者需要找最新内容，不能把新文章压在最下面
- 每页 15 篇，底部翻页控件（上一页/下一页）
- URL：`/categories/investment/` 等

### 6. 编号格式

**决策：编号格式为 `{prefix}-{3位序号}`，例如 `inv-001`、`tool-012`。**

- 前缀使用小写英文字母
- 序号固定 3 位（前补零）
- 由作者手动分配，在同一分类内唯一

### 7. Hugo frontmatter 字段

**决策：新增 `category` 和 `number` 两个字段。**

```yaml
---
title: 为什么我更看好国证自由现金流
date: 2025-01-15
category: investment
number: "001"
tags: [ETF, 指数投资, 自由现金流]
---
```

注册 `category` 为 Hugo taxonomy：
```toml
# hugo.toml
[taxonomies]
  category = "categories"
```

### 8. 编号展示

- **文章详情页**：编号显示在标题附近，小字号，灰色
- **列表页（分类/标签）**：每条目右侧显示编号
- **首页缩略图格**：编号显示在图片右下角或标题下方

## Risks / Trade-offs

**[风险] 分类边界模糊：** 如「从备孕悟出的人生道理」既可 `growth` 也可 `insight`。
→ **缓解：** 以写作时的**主要动机**判断；规则不需要完美，允许个案灵活处理。

**[风险] 缩略图缺失影响首页美观：** 部分文章没有 `cover` 图片。
→ **缓解：** 用纯色块替代，不破坏布局；后续可补充封面图片。

**[权衡] 手动编号 vs 自动编号：** 手动更灵活（可反映重要性），但负担较大。初期手动，待期引入辅助脚本。

## Migration Plan

1. **第一步：** 确定分类和编号规则，修改 2-3 篇最新文章 frontmatter 作为试点，验证效果
2. **第二步：** 注册 `category` 为 Hugo taxonomy，更新 `hugo.toml`
3. **第三步：** 更新顶栏导航（改为分类入口），更新 `about` 页面占位
4. **第四步：** 定制首页为 Hero + 缩略图网格，定制分类页为纯列表
5. **第五步：** 批量为所有历史文章添加 `category` 和 `number` 字段
6. **回滚：** 删除 `category`/`number` 字段，撤销 `hugo.toml` taxonomy 配置，恢复顶栏导航——全部可逆
